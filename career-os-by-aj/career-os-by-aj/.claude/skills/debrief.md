# Interview Debrief

Capture interview notes and prepare for the next round.

## Arguments
- Company name or path to application folder

## Prerequisites
- Application folder must exist with role_description.md and fit_analysis.md
- pipeline.md should show this role in active interview stage

## Process

### Step 1: Capture
Ask the user:
1. Who did you speak with? (Name, title, role in hiring process)
2. How long was the conversation?
3. What format? (Phone, video, in-person, panel)
4. Walk me through the key questions they asked and how you answered.
5. What did you learn about the role/team/company that wasn't in the JD?
6. Any red flags or concerns raised (by either side)?
7. Did they mention compensation? Next steps? Timeline?
8. How do you feel it went? (1-10)

### Step 2: Analyze
1. Identify what went well and what could improve
2. Flag any new information that changes the fit analysis
3. Note any questions the user wished they'd answered differently

### Step 3: Next Round Prep (if applicable)
1. Based on interviewer role and intel gathered, predict the next interviewer's angle
2. Suggest 3-5 stories from stories.md (or profile.md if no stories exist yet) to prepare
3. Draft 3-5 questions the user should ask in the next round
4. Identify any preparation gaps (research, practice answers, materials to review)

### Step 4: Save
1. Save to `interview_notes.md` in the application folder:
   ```
   ## [Round N] Debrief - [Interviewer Name] | [Date]
   **Format:** [Phone/Video/In-person]
   **Duration:** [time]

   ### Key Intel
   - [what was learned]

   ### Questions Asked & Answers Given
   - Q: [question] | A: [summary of answer] | Assessment: [good/ok/weak]

   ### Red Flags / Concerns
   - [any concerns]

   ### Compensation / Next Steps
   - [what was discussed]

   ### Next Round Prep
   - Likely interviewer: [name/role]
   - Stories to prepare: [list]
   - Questions to ask: [list]
   ```
2. Update pipeline.md with new stage and next action
3. If new profile information surfaced, update profile.md

### Step 5: Story Bank
If the interview revealed a good story the user told well, offer to add it to stories.md in STAR format:
```
## [Story Title]
**Tags:** [leadership, crisis, cost-saving, etc.]
**Situation:** [context]
**Task:** [what needed to happen]
**Action:** [what the user did]
**Result:** [outcome with metrics if possible]
**Best for:** [types of questions this answers]
```

## Rules
- Record facts, not impressions - unless the user explicitly shares their read
- Don't sugarcoat weak answers - the user needs honest assessment to improve
- Update pipeline.md immediately after debrief
- If the user got rejected, help them extract lessons, then mark as closed in pipeline
